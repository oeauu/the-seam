# 01 当前仓库审计

## 1. 审计结论

当前仓库已经具备一个完整度较高的前端原型，不应推倒重来。

它已经包含：

- React 19 + TypeScript + Vite
- D3 与 TopoJSON 驱动的二维地图
- 世界、洲、国家、省级多级下钻
- 单年份时间轴与自动播放
- 双语界面
- 档案详情抽屉
- 档案网格、编年、来源和关键词视图
- 投稿表单与审核队列原型
- 证据等级、解释风险和文化意义标签
- 博物馆式基础视觉系统
- 二维回退目录

因此，本轮应采取渐进式重构。

## 2. 当前主要技术结构

### 2.1 依赖

`package.json` 当前包含：

- React
- React DOM
- Vite
- TypeScript
- D3
- TopoJSON
- 中国地图 GeoJSON 依赖
- Oxlint

当前没有 Three.js、React Three Fiber、测试框架和端到端测试框架。

### 2.2 关键文件

- `src/App.tsx`
  - 约 1200 行
  - 管理主导航、语言、筛选、时间、地图层级、投稿、审核、统计和页面渲染
  - 已明显承担过多职责

- `src/components/InteractiveMap.tsx`
  - 约 970 行
  - 使用 D3 直接操作 SVG
  - 包含投影、缩放、地图绘制、多级下钻、地点锚点和弹框逻辑
  - 适合作为二维回退，不适合继续堆叠三维逻辑

- `src/components/TimeTravelTimeline.tsx`
  - 单年份滑块
  - 固定时间刻度
  - 支持自动播放
  - 当前以精确年份相等作为事件匹配条件

- `src/db/mockData.ts`
  - 详情卡片主数据

- `src/db/eventsData.ts`
  - 地图和时间轴事件数据

- `src/db/geography.ts`
  - 国家、地区、城市和坐标数据

- `src/index.css`
  - 约 2600 行
  - 已形成较完整视觉系统，但文件过大

- `lost_features_analysis.md`
  - 已记录重构过程中丢失的自动导览、纪元预设、多事件弹框、审核编辑和提示气泡等能力

## 3. 当前优势

### 3.1 业务结构已经形成

项目不是单纯地图演示。它已经具有档案、来源、证据、投稿、审核和多语言框架。这些都应保留。

### 3.2 二维地图具有回退价值

现有 D3 地图支持多级地理下钻，虽然视觉与目标不同，但非常适合成为：

- WebGL 不可用时的回退
- 减少动态效果模式
- 低性能移动设备模式
- 无障碍替代视图

### 3.3 视觉方向基本正确

当前样式已经使用博物馆式、档案式语言，没有把项目做成彩虹霓虹风。后续需要收敛 emoji、临时图标、内联样式和不一致的视觉细节，而不是重新建立完全不同的品牌。

## 4. 当前关键问题

### 4.1 主数据重复

`MOCK_ENTRIES` 和 `EVENTS_DATA` 分别驱动详情与地图。

两者通过地点字符串和年份近似匹配，存在以下问题：

- 同一条记录需要维护两次
- 地点名称中英文和层级不一致时匹配失败
- 投稿获批后通过字符串猜测年份
- 地图、档案页和详情可能显示不同数据
- 同地点多条记录难以稳定对应

本轮必须合并为单一 `ArchiveEntry` 数据模型。

### 4.2 时间系统过于离散

当前时间轴只选择一个年份，并磁吸到固定刻度。

问题包括：

- 不能表达一个时期
- 不能表达模糊时间
- 不能表达长期流传
- 不能表达时间不详
- 条目必须与选中年份完全相等才出现
- 当前存在“公元 0 年”显示

本轮必须改为时间范围筛选。

### 4.3 组件过大

`App.tsx` 和 `InteractiveMap.tsx` 已超过合理维护规模。

继续在其中加入 Three.js 会导致：

- 状态相互影响
- 渲染逻辑难以测试
- 二维与三维代码耦合
- 相机、筛选、详情和导航难以复用
- 后续接入后端困难

本轮必须拆分为独立 feature 模块。

### 4.4 类型纪律不足

当前存在：

- `any[]`
- D3 数据大量使用 `any`
- 投稿数据无统一接口
- `getCombinedEvents()` 每次创建新数组
- useMemo 依赖中包含非稳定函数
- 字符串作为枚举和地理标识

本轮应建立严格类型、解析函数和选择器。

### 4.5 数据内容仍属于演示状态

当前示例数据中包含大量需要重新核验的时间、地点和叙述。

本轮不是史料研究任务，不应擅自修订或扩充历史事实。技术迁移时应：

- 保留现有内容作为演示数据
- 标注 `contentStatus: "demo"`
- 界面可显示“演示数据”提示
- 不将演示内容写入正式策展声明

### 4.6 缺少测试

当前项目没有：

- 单元测试
- 组件测试
- 端到端测试
- 三维回退测试
- 性能基线

本轮必须建立最小测试体系。

### 4.7 README 仍为 Vite 模板

项目 README 仍是 React + Vite 模板说明，没有反映 The Queer Archive 的项目定位、运行方式和架构。

本轮完成后必须更新。

## 5. 参考视频能力与当前项目差距

| 参考效果 | 当前能力 | 本轮处理 |
| --- | --- | --- |
| 三维空间地图 | 二维 SVG 地图 | 新增三维地球和区域展台 |
| 大量图像卡片分层 | 地点圆点与弹窗 | 新增聚类、LOD 和档案卡片 |
| 平滑镜头推进 | D3 视图切换 | 新增相机状态与补间 |
| 选中作品居中展示 | 详情抽屉 | 新增三维聚焦并复用详情 |
| 时间影响空间对象 | 单年份精确匹配 | 改为范围相交与动画显隐 |
| 空间与编年双模式 | 档案页有静态编年 | 本轮只预留架构，不实现三维编年长廊 |
| 视觉密度很高 | 当前条目较少 | 先实现可扩展性能策略，不伪造大量正式条目 |

## 6. 本轮应保留的旧功能

- D3 二维地图
- 多级地理数据
- 详情抽屉
- 双语切换
- 搜索和分类
- Archive 页面
- 投稿与审核原型
- lost features 文档中仍有价值的功能设计

## 7. 本轮应替换或重构的旧机制

- `getCombinedEvents()`
- 地点字符串模糊匹配
- 单年份精确匹配
- `App.tsx` 中地图专属状态
- `InteractiveMap.tsx` 作为唯一地图入口
- 内联样式密集的地图页布局
- `any` 投稿模型
- 直接在 UI 中硬编码筛选标签

## 8. 基线检查要求

Codex 在修改前必须运行并记录：

```bash
npm install
npm run build
npm run lint
```

如果基线本身失败，必须先记录失败，再做最小修复。不得把原始失败与新功能失败混为一谈。
