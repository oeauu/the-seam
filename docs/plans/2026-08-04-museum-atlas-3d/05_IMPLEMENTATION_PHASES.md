# 05 实施阶段

## 总体原则

所有阶段必须保持仓库处于可构建状态。

如果某阶段需要较大改动，应先建立兼容层，再替换旧机制。

Codex 可以使用多个子任务并行分析，但代码集成必须由一个主执行上下文统一完成。不得让多个子任务同时修改相同核心文件。

## Phase 0：基线、分支与任务记录

### 目标

建立可追溯的执行基线。

### 操作

1. 拉取最新 `main`
2. 运行安装、构建和 lint
3. 记录当前失败与警告
4. 创建分支 `feat/museum-atlas-3d`
5. 新建执行记录草稿：

```text
docs/plans/2026-08-04-museum-atlas-3d/EXECUTION_REPORT.md
```

6. 更新报告中的基线部分

### 验收

- 已记录 Node、npm 和依赖版本
- 已记录 build 与 lint 基线
- 功能分支创建成功

## Phase 1：类型、测试和统一数据模型

### 目标

在进行三维开发前消除双数据源。

### 操作

1. 添加测试框架
2. 建立 `ArchiveEntry`、时间、地点、媒体和分类类型
3. 建立来源、对象类型和文化意义统一配置
4. 将 `MOCK_ENTRIES` 迁移为新模型
5. 合并 `EVENTS_DATA` 中独有信息
6. 建立选择器
7. 替换 `getCombinedEvents()`
8. 让现有二维地图、档案页和详情抽屉继续使用新数据
9. 当前数据统一标记为 `contentStatus: "demo"`

### 必测

- 时间范围格式化
- 无公元 0 年
- 范围相交
- 主地点选择
- 来源筛选
- 文化意义筛选
- 按地区聚类

### 验收

- 地图、档案列表和详情使用同一数据源
- 旧页面行为基本不变
- 无 `any` 新增
- build、lint、unit test 通过

## Phase 2：Atlas 模块和二维回退入口

### 目标

建立三维模块边界，不立即替换旧地图。

### 操作

1. 创建 `src/features/atlas`
2. 创建 `AtlasViewport`
3. 将现有地图包装为 `Legacy2DMap`
4. 添加渲染模式：`auto | 3d | 2d`
5. 添加 WebGL 能力检测
6. 添加减少动态效果检测
7. 使用 React.lazy 懒加载三维模块
8. 地图页提供三维与二维显式切换

### 验收

- 默认支持环境进入三维占位场景
- 不支持环境进入二维地图
- 其他页面不加载 Three.js 主模块
- 回退切换不丢失筛选和选中条目

## Phase 3：全球地球与地区聚类

### 目标

完成全球尺度的核心体验。

### 操作

1. 添加 Three.js、React Three Fiber 和 Drei
2. 创建 `GlobeScene`
3. 实现地球材质和国界线
4. 实现 `latLngToVector3`
5. 实现地区聚类选择器
6. 创建 `ClusterMarker3D`
7. 添加 Orbit 或 CameraControls
8. 添加悬停说明
9. 添加点击地区事件
10. 添加地球初始加载状态

### 视觉要求

- 不使用金色奢华风
- 地球边界清楚但克制
- 聚类点像馆藏标记
- 不直接铺满图片

### 验收

- 可以旋转、缩放
- 聚类位置正确
- 筛选变化后数量更新
- 点击聚类能设置选中地区
- Canvas 失败时回退二维
- build、lint、test 通过

## Phase 4：区域档案展台

### 目标

实现参考视频中最关键的“地图上方出现文化对象”能力。

### 操作

1. 建立区域地图投影工厂
2. 将 GeoJSON 绘制为 Canvas 纹理
3. 创建 `RegionAtlasScene`
4. 将条目地点映射到区域平面坐标
5. 创建 `ArchiveCard3D`
6. 创建无图、文献、口述、法律等卡片模板
7. 建立地点聚类
8. 实现全球到区域的镜头过渡
9. 添加返回全球按钮
10. 加载当前区域所需纹理，离开后释放

### 验收

- 至少三个不同地区可进入区域展台
- 区域地图轮廓与卡片地点一致
- 同地点多条记录不会互相完全遮挡
- 无图条目有合理展示
- 返回全球后相机状态稳定

## Phase 5：时间范围与筛选联动

### 目标

将当前单年份时间轴升级为真正的历史范围控制器。

### 操作

1. 新建 `AtlasTimeline`
2. 实现起止年份双滑块
3. 实现手动年份输入
4. 实现 BCE 和 CE 格式
5. 实现范围预设
6. 实现时间不详开关
7. 让来源与文化意义筛选使用统一状态
8. 让三维和二维视图共享筛选结果
9. 添加卡片显隐动画
10. 保证拖动过程不频繁重建场景

### 验收

- 可输入和拖动年份
- 不显示公元 0 年
- 时间范围相交逻辑正确
- 三维卡片与二维地图结果一致
- 来源和文化意义筛选实时联动
- 快速拖动不导致明显卡顿或崩溃

## Phase 6：档案聚焦与详情整合

### 目标

完成从空间浏览到单件档案观看的连续体验。

### 操作

1. 创建 `AtlasCameraRig`
2. 保存进入聚焦前的相机姿态
3. 实现点击卡片后的平滑聚焦
4. 创建 `AtlasDetailOverlay`
5. 复用现有 `DetailsDrawer`
6. 添加查看完整档案按钮
7. 添加关闭、ESC 和浏览器返回
8. URL hash 恢复场景状态
9. 关闭后恢复区域相机
10. 动画期间阻止重复点击

### 验收

- 点击卡片后镜头平滑推进
- 详情信息正确
- 返回后恢复原视角
- ESC 和浏览器返回有效
- 深链接可以打开指定条目
- 焦点管理符合无障碍要求

## Phase 7：性能、自适应与移动端

### 目标

让功能在真实设备上可用。

### 操作

1. 加入性能监测
2. 自适应 DPR
3. 限制活动纹理数量
4. 远景聚类、中景代表卡、近景具体卡
5. 移动端减少卡片
6. 移动端详情改为底部抽屉
7. 低性能自动回退二维
8. 添加图片错误占位
9. 添加 GeoJSON 错误回退
10. 检查内存释放

### 验收

- 桌面普通设备操作流畅
- 移动端不出现不可操作的小控件
- 图片损坏不崩溃
- 三维失败自动回退
- 反复进入不同地区不持续增长内存

## Phase 8：恢复有价值的旧功能

### 目标

从 `lost_features_analysis.md` 中恢复与新架构兼容的能力。

### 本轮优先

1. 同地点多事件列表
2. 证据等级和解释风险说明气泡
3. 历史时期预设

### 可延后

1. 自动策展导览
2. 审核元数据原地编辑

如果前三项影响主计划进度，可以将其写入执行报告的下一阶段，不得用仓促实现破坏主体验。

## Phase 9：测试、文档与收尾

### 操作

1. 补齐单元测试
2. 补齐组件测试
3. 编写最小 Playwright 测试
4. 运行 build、lint、unit、e2e
5. 更新 README
6. 记录新架构与目录
7. 完成 `EXECUTION_REPORT.md`
8. 检查依赖是否重复
9. 检查死代码和未使用资源
10. 推送功能分支

### README 至少包括

- 项目简介
- 当前功能
- 运行命令
- 三维与二维地图说明
- 数据为演示状态的说明
- 技术架构
- 计划目录链接

## 阶段间停止条件

出现以下情况时，不得继续叠加功能：

- build 失败
- TypeScript 错误
- 现有档案页面无法访问
- 二维地图丢失
- 详情抽屉无法打开
- 筛选结果在二维与三维中不一致
- 纹理加载导致持续崩溃

应先修复当前阶段，再进入下一阶段。
