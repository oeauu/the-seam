# Legacy 应用隔离边界

## 状态与范围

本目录用于标记旧应用的隔离边界，供开发、对照和问题追踪使用。当前这次限界任务只新增本说明文件；没有移动、重命名、删除或重写旧实现，也没有声称 `src/archive-app/` 已经建立或完成迁移。

旧实现仍属于 legacy。它不是新档案应用的入口，也不是 V4 验收结果的证据。只有在 V4 计划明确要求、并有对应测试和交付记录时，才能改变这里列出的边界。

## 为什么隔离旧实现

- `src/App.tsx` 是旧应用的根级编排和页面入口，包含旧页面状态、筛选、列表与旧组件之间的耦合。让新应用继续从它启动，会把旧的页面生命周期和状态模型带入新边界。
- `src/index.css`、`src/App.css` 是旧应用的全局样式层，包含宽泛的元素、类名和 ID 选择器，例如 Globe、时间轴和抽屉相关规则。它们可能通过级联、布局高度、溢出和 z-index 影响羊皮卷页面滚动及新应用的局部样式，因此不应成为新应用的样式基础。
- `src/features/atlas/components/GlobeScene.tsx` 与 `src/features/atlas/components/RegionAtlasScene.tsx` 属于旧 Atlas/球形 GlobeScene 路径及其区域场景假设。它们围绕旧的 3D 场景组织方式工作，不应被当作 V4 羊皮卷世界地图的实现或适配层；继续修补它们也不等于完成 V4。
- 旧的时间轴、详情抽屉以及 `Auto` / `3D` / `2D` 模式按钮代表旧的覆盖层和显式模式切换交互。V4 的目标是正常页面滚动、羊皮卷下端时间轴、金色坐标、档案抽屉和自动兼容回退。保留旧控件作为新交互的依赖，会重新引入旧的状态、DOM、样式和模式分支。

因此，隔离的目的不是把旧代码改名后继续复用，而是让新入口可以独立验证、独立回退，并能明确识别仍未迁移的能力。

## 新应用的依赖禁令

`src/archive-app/` 一旦建立，必须保持独立的入口和依赖图：

1. 不得从 `src/legacy/`、旧 `src/App.tsx`、旧全局 CSS、`GlobeScene`、`RegionAtlasScene`、旧时间轴、旧详情抽屉或旧 `Auto` / `3D` / `2D` 控件导入运行时代码、状态、样式或 DOM 约定。
2. 不得通过全局选择器、共享可变状态、事件总线、隐式单例或复制旧模式按钮来形成间接依赖。新应用应在自己的边界内定义页面滚动、场景、时间轴、坐标和抽屉交互。
3. 旧文件即使暂时保留，也不能因为“兼容”或“占位”而被接入新入口。需要复用的能力必须先在 V4 计划中明确边界、来源、测试和迁移结果；本 README 不授权任何迁移。
4. 新应用的构建和验收不能以 legacy 页面能否运行来替代 V4 功能验收，也不能把旧 GlobeScene 的截图或旧控件的行为计为 V4 完成。

## 开发环境中的 legacy 查看入口

legacy 查看入口只能是开发期、显式、可移除的诊断入口，并须满足以下约束：

- 不得替换根路径或新 `src/archive-app/` 入口，不得自动重定向用户进入 legacy。
- 只能在开发环境启用（例如由明确的开发环境条件控制）；不得把入口、导航按钮或 legacy 资源作为生产界面的一部分发布。
- 入口必须明确标注为 Legacy/旧版，且只用于对照、回归排查和迁移前后的差异确认；它不应被用作 V4 的默认演示路径。
- legacy 查看不应要求新应用加载旧全局 CSS、旧模式按钮或旧场景组件。若临时诊断确实需要旧依赖，依赖必须限制在 legacy 自己的入口图中，并有可重复的启动说明。
- 本次变更没有创建或承诺一个实际的 legacy 开发路由；在没有独立入口、环境门控和对应测试之前，不得把任意现有 URL 称为已完成的 legacy 查看入口。

## 本轮非目标与未完成事项

本轮只建立隔离说明，不包含以下工作：

- 不迁移或实现 `src/archive-app/`，不实现三维羊皮卷世界地图、正常页面滚动、拖动/缩放、下端时间轴、金色坐标、档案抽屉或自动兼容回退。
- 不修改或继续修补球形 `GlobeScene`、`RegionAtlasScene`、旧控制台布局、旧全局 CSS，或生产界面的 `Auto` / `3D` / `2D` 按钮。
- 不迁移旧数据、资源、测试、状态管理或视觉样式；不删除旧文件，也不宣称旧实现已被彻底移出构建图。
- 不建立实际的开发路由、CI、三维截图或交互录制；这些只有在 V4 计划的相应阶段中完成并通过验收后才能报告为完成。
- 不运行或报告 V4 的阶段测试结果，不生成执行报告，不提交、不推送，也不创建 PR。

后续若要结束 legacy 生命周期，必须先完成新应用的独立实现和验收，再由计划明确规定迁移、删除或保留策略，并留下可核验的测试与交付证据。

## V4 实际边界更新

V4 实施阶段已经把原 `src/App.tsx` 移动为 `src/legacy/LegacyApp.tsx`，并把新的根入口改为 `src/archive-app/AppRoot.tsx`。开发模式下可用 `?legacy=1` 显式查看旧应用；生产构建不会启用该查询入口。V4 的正式路径、测试、截图和报告均针对新应用，不把 legacy 视为完成证据。
